# Автоповтор и зажатие клавиш: как это делают Windows и Linux, и как повторить на своей прошивке (H3 / bare metal)

## 1. Кто на самом деле делает «повторы»

Железо (и донгл Avatto, и обычная PS/2-клавиатура) при удержании клавиши
ШЛЁТ ОДИН пакет «клавиша нажата» и ДЕРЖИТ код в отчёте до отпускания.
Никаких повторных пакетов аппаратура не генерирует.

Автоповтор — это **программная эмуляция в ОС**:

| | Windows | Linux |
|---|---|---|
| Драйвер | kbdclass.sys | ядро, KBD autorepeat |
| Параметры | KeyboardDelay, KeyboardSpeed | kbdrate (delay, rate) |
| Время до 1-го повтора | 250–1000 мс (по умолчанию ~500) | ~250 мс (по умолчанию) |
| Период повторов | ~30–500 мс (по умолчанию ~30) | ~33 мс (30 Гц) |
| Как выглядит в API | WM_KEYDOWN с битом повтора (lParam bit 30) | EV_KEY value=1, потом value=2…, value=0 |

Запомните: повторы существуют ТОЛЬКО для старых программ, которые слушают
события, но не умеют узнавать состояние клавиши. Современные играм это почти
не нужно.

## 2. Как игра на самом деле читает клавиатуру

Игровой цикл делает так (упрощённо):

```
while (running) {
    update_input_state();   // опросить состояние всех клавиш
    // дальше — работа с "нажата сейчас?" а не с "пришло событие нажатия"
}
```

Игры опрашивают состояние:
- Windows: `GetAsyncKeyState(VK_W)` в каждом кадре, или DirectInput/
  Raw Input (там тоже состояние), или GameInput.
- Linux: SDL/GLFW держат таблицу «клавиша нажата/отпущена» из событий
  press/release.

Поэтому для игры достаточно, чтобы ваша прошивка корректно выдала
**PRESS → (пауза) → RELEASE**. Автоповтор игре не нужен и чаще мешает.

## 3. Почему у вас «залипание» или «приходится долбить»

### Симптом А. «Залипание» (клавиша словно нажата навсегда)
Причина: вы послали PRESS, но RELEASE не дошёл/потерялся, или игра не увидела
очистку состояния. Логика игры: «клавиша в состоянии down = делай». Один
потерянный release = вечное зажатие.

Что делать:
- Проверять всю цепочку: отчёт «все нули» после отпускания, отсутствие
  повторных «зависших» пакетов.
- Слать состояние циклически (heartbeat): не «событие раз в момент смены»,
  а «текущее состояние каждые 10–20 мс». Тогда даже потерянный пакет
  восстановится следующим.
- Watchdog: если нет отчётов от донгла N мс (например 100 мс) — принудительно
  «отпустить» все клавиши (послать пустой отчёт).

### Симптом Б. «Приходится долбить» (нет повторов, действие срабатывает разово)
Причина: либо ваша программа ждёт событий повтора (как ОС), а донгл их не
шлёт; либо игра читает состояние, а вы шлёте одиночные press/release — игра
видит «мигание», а не зажатие.

Два разных случая:

1) Вы выступаете как **USB-клавиатура** (H3 = HID gadget, транслирует
   нажатия донгла в ПК).
   Решение: при удержании держите код в boot-отчёте (не отпускайте),
   пустой отчёт — только при реальном отпускании. ОС сама сделает автоповтор,
   игры увидят зажатое состояние. Ничего дополнительно слать не нужно.

2) Вы сами в своей программе обрабатываете «удержание» (без ОС).
   Решение: эмулируйте автоповтор сами таймером (см. раздел 5), либо
   работайте от состояния, а не от событий.

## 4. Как Windows генерирует повтор (для тех, кто пишет под Windows)

- `WM_KEYDOWN`: bit 30 в `lParam` = 1 означает «это автоповтор, клавиша уже
  была нажата и держится». Программы, которые считают нажатия по событиям,
  ДОЛЖНЫ игнорировать такие сообщения или не считать повтор вторым нажатием.
- Задержка и скорость: `Control Panel → Клавиатура` (до SystemsParametersInfo
  SPI_GETKEYBOARDDELAY/SPEED) или реестр `HKCU\Control Panel\Keyboard`
  (KeyboardDelay 0–3, KeyboardSpeed 0–31).
- Играм, работающим через `GetAsyncKeyState`, эти настройки безразличны:
  они видят просто «нажата».

## 5. Готовый рецепт для вашей прошивки на H3

### 5.1. Если H3 — транслирующая USB-клавиатура
```
при чтении отчёта с донгла:
    if код появился:      запомнить код = 1
    if код исчез:         запомнить код = 0
каждый тик (10 мс):
    собрать boot-отчёт из запомненных кодов
    отправить отчёт в USB gadget   // держим код, пока не отпущен
```
Больше ничего: автоповтор и «зажато в игре» сделает ОС.

### 5.2. Если нужно эмулировать автоповтор самому
```
на каждый удерживаемый код:
    repeat_tick = 0
    если код держится дольше REPEAT_DELAY (=300 мс):
        repeat_tick++
        если repeat_tick >= REPEAT_PERIOD (=120 мс):
            do_action(code)          // «повторное нажатие»
            repeat_tick = 0
при отпускании: repeat_tick = 0
```

### 5.3. Дебаунс и защита от потерь
```
- игнорировать «мелькание» короче 10–15 мс
- слать состояние, а не моментные события (heartbeat 20 мс)
- watchdog 100 мс без данных от донгла → отпустить все клавиши
- никогда не зависать в ожидании пакета без тайм-аута
```

## 6. Короткая шпаргалка

| Сценарий | Что слать |
|---|---|
| Игра ждёт зажатие | держать код в отчёте, RELEASE только при реальном отпускании |
| Старая программа ждёт повторы | эмулировать пары press/release по таймеру (delay 300 мс, period 120 мс) |
| ОС увидела «залипание» | чинить потерю release: heartbeat + watchdog + дебаунс |
| Нужно «клик» разово | press + release с паузой 20–50 мс |

## 7. Проверка без игры

На Windows:
```
PowerShell:  [System.Windows.Forms.SendKeys] не подойдёт — это синтез.
Проверка RAW: посмотреть свойства клавиатуры → «Скорость повтора»
(ползунок "Задержка до начала повтора", "Скорость повтора") —
это и есть тот самый механизм, который вы должны обойти/повторить.
```
На Linux:
```
kbdrate -d 300 -r 15   # пример: задержка 300 мс, частота 15 Гц
```
(команда применится к консольной клавиатуре; в X/Wayland используйте
настройки DE: Повтор клавиш → задержка и скорость.)
